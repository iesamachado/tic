11. Programación JavaScript Clásico

Dándole cerebro e interactividad a tu página web.

1. El DOM: Controlando el HTML

JavaScript (JS) es el lenguaje de programación que se ejecuta dentro del navegador. Su trabajo principal es manipular el DOM (Document Object Model), que es la estructura de tu web.

Para cambiar algo en tu página, primero tienes que "atrapar" el elemento usando su ID:

// 1. Capturamos el elemento con id="titulo"
const miTitulo = document.getElementById('titulo');

// 2. Le cambiamos el texto
miTitulo.innerText = "¡Hola Mundo desde JS!";

// 3. Le cambiamos el estilo CSS (ej. el color)
miTitulo.style.color = "red";

2. Eventos: Escuchando al Usuario

Las webs son interactivas gracias a los eventos (clicks de ratón, movimientos, pulsaciones de teclado). Para reaccionar a ellos usamos addEventListener.

Capturar el Teclado

Si estás haciendo un juego, necesitas saber cuándo el jugador pulsa las flechas del teclado. El evento keydown se dispara cuando hundes la tecla, y keyup cuando la sueltas.

document.addEventListener('keydown', (evento) => {
  if (evento.key === "ArrowRight") {
    console.log("El jugador ha pulsado la flecha derecha");
  } else if (evento.key === "Space") {
    console.log("¡Saltar!");
  }
});

3. Práctica: Cómo mover una imagen con el teclado

Vamos a combinar los dos conceptos anteriores. Imagina que tienes en tu HTML una imagen de un personaje con posicionamiento absoluto:

<!-- En tu index.html -->
<img id="personaje" src="mario.png" style="position: absolute; left: 50px; top: 100px;">

Ahora, en JavaScript, capturamos esa imagen, creamos una variable para guardar sus coordenadas, y la modificamos cada vez que pulsemos las flechas:

// 1. Capturamos la imagen
const jugador = document.getElementById('personaje');

// 2. Guardamos su posición X (horizontal) y Y (vertical)
let posicionX = 50;
let posicionY = 100;
const VELOCIDAD = 10;

// 3. Escuchamos las teclas
document.addEventListener('keydown', (evento) => {
  
  if (evento.key === "ArrowRight") {
    posicionX = posicionX + VELOCIDAD; // Sumar mueve a la derecha
  } 
  else if (evento.key === "ArrowLeft") {
    posicionX = posicionX - VELOCIDAD; // Restar mueve a la izquierda
  }
  else if (evento.key === "ArrowDown") {
    posicionY = posicionY + VELOCIDAD; // En la web, Y positivo es hacia abajo
  }
  else if (evento.key === "ArrowUp") {
    posicionY = posicionY - VELOCIDAD; // Y negativo es hacia arriba
  }

  // 4. Aplicamos las nuevas coordenadas al CSS (¡importante poner 'px'!)
  jugador.style.left = posicionX + "px";
  jugador.style.top = posicionY + "px";
});

4. Programación Orientada a Objetos (OOP)

Hasta ahora hemos usado JavaScript de forma procedimental: instrucciones que se ejecutan una tras otra. Pero hay una forma más potente de organizar el código: la Orientación a Objetos (OOP). En lugar de funciones sueltas, creamos Clases que son como plantillas para crear objetos con sus propias propiedades y comportamientos.

La Clase: una Plantilla

Imagina que tienes que crear varios aliens para el Hex Invaders. En lugar de repetir código para cada uno, defines una plantilla:

// Definimos la plantilla (Clase)
class Alien {
  constructor(color, posicionX) {
    // 'this' hace referencia al objeto que se va a crear
    this.color = color;
    this.posicionX = posicionX;
    this.posicionY = 0; // Todos los aliens empiezan arriba
    this.vivo = true;
  }

  // Método: acción que puede hacer el objeto
  caer(velocidad) {
    this.posicionY = this.posicionY + velocidad;
  }

  explotar() {
    this.vivo = false;
    console.log("¡El alien " + this.color + " ha sido destruido!");
  }
}

El Objeto: una instancia de la Clase

Una vez tienes la plantilla, puedes crear tantos aliens como quieras con new:

// Creamos objetos usando la clase como plantilla
const alien1 = new Alien("#FF0000", 10);
const alien2 = new Alien("#00FF00", 42);
const alien3 = new Alien("#0000FF", 75);

// Llamamos a los métodos de cada objeto
alien1.caer(5);
alien2.caer(5);

// Cada alien recuerda su propio estado
console.log(alien1.posicionY); // 5
console.log(alien2.posicionY); // 5

alien1.explotar(); // "¡El alien #FF0000 ha sido destruido!"

Herencia: Clases que extienden a otras

Si quisieras un "Alien Jefe" que tenga todo lo del Alien normal pero además tenga el doble de vida, usarías extends:

class AlienJefe extends Alien {
  constructor(color, posicionX) {
    super(color, posicionX); // Llama al constructor del padre
    this.vida = 3; // El jefe necesita 3 impactos para morir
  }

  recibirImpacto() {
    this.vida--;
    if (this.vida <= 0) {
      this.explotar();
    } else {
      console.log("¡El jefe resiste! Vida restante: " + this.vida);
    }
  }
}

const jefe = new AlienJefe("#FF00FF", 40);
jefe.recibirImpacto(); // "¡El jefe resiste! Vida restante: 2"
jefe.recibirImpacto(); // "¡El jefe resiste! Vida restante: 1"
jefe.recibirImpacto(); // "¡El alien #FF00FF ha sido destruido!"

13. Algoritmos, Pseudocódigo y Depuración

Pensar antes de programar: el arte de diseñar soluciones antes de escribir código.

1. ¿Por qué no pedirle todo directamente a la IA?

Imagina a un cocinero que solo sabe seguir recetas al pie de la letra sin entender por qué se echa sal o por qué se calienta el horno. Si algo sale mal, no sabrá arreglarlo. Lo mismo pasa si le pides a la IA que te genere un código y lo pegas sin entenderlo: la IA genera código correcto, pero tú no sabrás qué hace ni cómo depurarlo cuando falle.

El verdadero valor de un programador hoy no es memorizar sintaxis, sino saber DISEÑAR la solución.

El Algoritmo 🧠

Un algoritmo es una secuencia finita y ordenada de pasos para resolver un problema. Piensa en ello como una receta de cocina o las instrucciones detalladas de un juego de mesa.

2. Top-Down: divide y vencerás

El enfoque Top-Down consiste en partir de un problema grande y complejo y descomponerlo en subproblemas pequeños y manejables.

Ejemplo: SuperMarioBros 🍄

¿Cómo se programa un juego tan grande? Descomponiéndolo en módulos (funciones):

  • Renderizado de pantalla
  • Físicas y gravedad
  • Entrada del jugador (teclado/mando)
  • Sistema de puntuación
  • Gestión de niveles

Analogía con el podcast: Antes de grabar, se divide el proyecto en fases: preproducción → grabación → postproducción → distribución. Cada fase tiene sus propias subtareas. ¡Eso es pensar Top-Down!

3. Pseudocódigo — el borrador del código

El pseudocódigo es una representación del algoritmo en lenguaje natural estructurado. Es independiente del lenguaje de programación (no importa si luego usas JS, Python o C++).

Reglas básicas de vocabulario: INICIO/FIN, LEER/ESCRIBIR, SI...ENTONCES...SINO, MIENTRAS, PARA.

Ejemplo: Movimiento de Mario a la derecha

INICIO
  posicionX ← 50
  velocidad ← 10
  MIENTRAS (jugando = VERDADERO)
    LEER tecla_pulsada
    SI tecla_pulsada = "ArrowRight" ENTONCES
      SI posicionX + velocidad < limite_derecho ENTONCES
        posicionX ← posicionX + velocidad
      FIN SI
    FIN SI
    ESCRIBIR posicionX en pantalla
  FIN MIENTRAS
FIN

4. Diagramas de Flujo

Otra forma visual de representar algoritmos. Utilizan formas geométricas estándar conectadas por flechas:

  • Óvalo: Inicio / Fin
  • Rectángulo: Proceso o acción
  • Rombo: Decisión (Sí / No)
  • Paralelogramo: Entrada / Salida de datos

Herramientas recomendadas para dibujarlos: diagrams.net (draw.io) o Google Dibujos.

5. Depuración (Debugging) 🐛

El origen del término 'bug' (bicho) en informática se remonta a 1947, cuando la pionera Grace Hopper encontró una polilla real atrapada en el relé de un ordenador que causaba fallos.

Tipos de Errores

  • De Sintaxis: El código está mal escrito (falta una coma o un paréntesis). El ordenador ni siquiera puede ejecutarlo.
  • De Lógica: El código se ejecuta, pero hace algo incorrecto (ej. Mario suma puntos en vez de perderlos al chocar con un enemigo).
  • Intermitentes: Solo ocurren bajo ciertas condiciones extrañas.

Técnicas de Debugging

1. La Consola (F12): Abre las DevTools de tu navegador, ve a la pestaña Console y lee el mensaje de error en rojo. Te dirá en qué línea está el fallo.

2. El console.log(): Inserta mensajes en tu código para ver qué valor tienen las variables en un momento dado.
